# Независимая кодовая база Linux

Решение принято пользователем 14 ноября 2026. Linux-клиент полностью отделяется от кодовой базы Windows: совпадающий код разрешено однократно скопировать в Linux-репозиторий, после чего он развивается и проверяется здесь самостоятельно. Это позволяет переносить изменения Windows без зависимости Linux-разработки и выпусков от структуры и веток Windows.

- Подмодуль `shared/` заменяется обычными файлами, отслеживаемыми Linux-репозиторием. Зависимость от Windows-репозитория для клонирования, сборки, тестов и выпуска устраняется.
- Проекты, настройки сборки, ресурсы, необходимые тесты и инструменты становятся собственностью Linux-проекта. Разделение на внутренние модули сохраняется там, где оно полезно Linux.
- При переносе изменений из Windows фиксируются исходный коммит и происхождение кода; сохраняются лицензии и уведомления об авторстве. Windows-специфичные реализации адаптируются под Linux.
- Последующие изменения вносятся непосредственно в Linux. Общих исходников, общей библиотеки между ОС и автоматической синхронизации с Windows больше нет. Будущие переносы выполняются явно, с самостоятельной проверкой Linux.
- SIP, Spark и канал обновлений сохраняют совместимость своих протоколов; независимость исходников не означает смену серверных контрактов.
- Цена решения — самостоятельное сопровождение исправлений и тестов, включая те, что позднее появятся в Windows.

## Порядок выполнения

1. Зафиксировать исходные коммиты Linux, `shared/` и Windows и составить перечень переносимых изменений по Windows `Mychanges.md`.
2. Превратить необходимое содержимое `shared/` в локальные исходники; удалить gitlink и настройку подмодуля, не затрагивая Windows-репозиторий.
3. Обновить ссылки проектов, настройки MSBuild, ресурсы, CI и скрипты сборки/выпуска: убрать загрузку Windows-репозитория и требования его меток. Сведения о происхождении сохранить как историю переноса.
4. Проверить сборку и тесты из чистого клона Linux без обращения к Windows-репозиторию.
5. Переносить актуальные исправления и интерфейс Windows отдельными этапами, адаптируя их для Avalonia, PulseAudio/PipeWire и Linux.

На момент принятия решения отделение исходников ещё не было выполнено; результат реализации записан в [отчёте этапа 2](../migration/2026-11-14-independent-code.md). Этот документ отменяет прежнее решение о совместном коде через подмодуль и соответствующие правила в `docs/PORT-PLAN.md`.
