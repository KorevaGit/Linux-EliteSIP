# Цвет обоев и аудит слабых ноутбуков — 1.0.1

Цель: AMD A6, 4 ГБ DDR3, HDD 500 ГБ, Linux Mint/Cinnamon/X11.
Проверены отрисовка, изображения, запись настроек, история, таймеры и границы
аудиотракта. Это не аппаратная сертификация: AMD A6/HDD/4 ГБ в распоряжении
нет. Замеры выполнены на i7-10750H, без ограничения частоты и сброса файлового
кэша. Холодный старт с HDD и CPU настоящего разговора здесь не измерены.

## Подтверждённые проблемы и исправления

1. Самая многочисленная квантованная группа цвета в фото оказалась почти
   белой. Прежний алгоритм превращал цветной режим в серый; прежние тесты
   с насыщенным однородным фоном этого не ловили. Теперь выбирается заметная
   цветная группа (chroma >= 24, saturation >= 15%, минимум 3% alpha-веса).
   Если такой нет, сохраняется нейтральный доминирующий цвет. Один маленький
   цветной пиксель не перекрашивает чёрно-белое фото. Формула кистей, контраст
   текста и семантические цвета вызовов сохранены. Проверены реальные кисти
   карточек окна и возврат к нейтральной тёмной теме.
2. Compose кодировал фон в PNG и немедленно декодировал в Avalonia на UI
   потоке. Заменено прямым копированием BGRA в WriteableBitmap. Размытие и
   яркость сохраняются, фон остаётся непрозрачным, bitmap общий для окон.
3. Автосохранение оформления и геометрии окон вызывало запись временного
   JSON и rename на каждое уведомление/движение. Linux объединяет эти записи
   таймером 350 мс на UI потоке, без гонки сериализации с изменениями модели.
   Pending save принудительно выполняется при Dispose и перед перезапуском.
   Остальные разделы сохраняются немедленно; настройки SIP/доступа не отложены.
4. 20-Гц опрос уровней звука продолжался в свёрнутых настройках. Теперь
   таймер приостановлен при скрытии/сворачивании, возобновляется при показе.
   Самопроверка/запись и аудиоустройства при этом не останавливаются.
5. История создавала все визуальные строки загруженных страниц. Теперь
   плоские заголовки/записи отображает VirtualizingStackPanel. Данные всё ещё
   загружаются страницами по 200, заголовки дней, фильтры, календарь, профиль
   и маскирование сохраняются. На 2000 записях проверено не более 60
   реализованных badges, прокрутка до последней записи и очистка фильтра.
6. Большие PNG могут не поддерживать уменьшение при декодировании: при
   прежнем пределе 100 МП временный BGRA занимал до 400 МБ. Теперь до
   выделения проверяется реальный размер scaled decode и предел 64 МиБ.
   Большое неподдерживаемое изображение нужно уменьшить перед импортом;
   рабочий фон по-прежнему не больше 1600 px по длинной стороне.

## Сравнительный замер

Команда: `ELITESIP_TEST_PERF=1 dotnet run --project tools/TrayProbe -c Release`.
Нативная X11-панель, синтетическое детализированное изображение 1600×1000,
8 изменений blur/brightness, затем по 10 секунд visible/hidden. Нет SIP,
захвата микрофона, обновляльщика и реального сервера. Один прогон до/после
изменения Compose; это не распределение результатов и не полный клиент.

| Метрика | До | После |
|---|---:|---:|
| 8 изменений фона | 1564 мс | 622 мс |
| Управляемые выделения на 8 изменений | 4 121 696 байт | 106 288 байт |
| RSS после изменений, visible | 237.2 МиБ | 207.8 МиБ |
| CPU visible за 10 с | 177 мс | 148 мс |
| CPU hidden за 10 с | 61 мс | 79 мс |
| Пересоздания фона/палитры в idle | 0/0 | 0/0 |

CPU idle между этими прогонами в пределах шума: улучшение idle не заявляется.
RSS включает нагрев стенда и нативные библиотеки, не только managed heap.
Поле startup_ms включает создание тестового PNG и прогрев: это **не** время
запуска установленного приложения, по нему не делается вывод о холодном HDD.
JSON и синтетические снимки: `low-end-2026-11-16/`.

## Что уже экономит ресурсы

- ReadyToRun в Release и self-contained пакет не требуют установки SDK.
- Общий предобработанный bitmap; resize не запускает размытие или выбор цвета.
- Декодирование импортируемых фото ограничено, оригинал не перечитывается
  при каждом resize; применение параметров фона объединяется на 120 мс.
- Массивы обработки/кодека выделяются до цикла capture, а не каждый 20-мс
  кадр. Нейросетевой шумодав в тракт не добавлялся.
- Лог уже имеет очередь и ротацию; события Spark сбрасываются пакетами.
- Ошибки выбора цвета и платформенные ограничения не исправляются
  отключением звуковой обработки или понижением надёжности приёма вызова.

## Проверки и дальнейшая аппаратная приёмка

Новые регрессии: белая область/цветной участок, grayscale/tiny accent, реальные
карточки темы, большой сжатый PNG, объединение 50 сохранений, flush при выходе,
пауза/возобновление meter polling без прерывания записи, 2000 строк истории.
Нативный X11: три внешних GTK-запроса буфера после закрытия виртуализированной
истории получили 1404×868; все колонки и строки fixture видны. Шесть вариантов
входящего и ранняя заставка также прошли стенд.

Для настоящего AMD A6/4 ГБ/HDD остаётся приёмка: 3 холодных запуска после
перезагрузки, 20 минут idle с CRM/браузером, 15 минут двустороннего разговора
с записью CPU/RSS/swap и xrun, входящий поверх CRM, история после смены
фильтров и установка обновления. Самопроизвольное swap/пропуски звука/паузы
UI более секунды требуют отдельного профиля; текущие замеры не обещают их
отсутствия на ноутбуке. Физическое исполнение и совместимость конкретных
моделей гарнитуры/видеодрайвера программными тестами не заменяются.
