# Этап 2 — независимые Linux-исходники

Дата: 14 ноября 2026. Статус: выполнен в рабочем дереве; коммит и публикация
Linux-репозитория не выполнялись. Решение: [ADR-0001](../adr/0001-independent-linux-codebase.md).
Исходные версии: [этап 1](2026-11-14-windows-parity.md).

## Что изменено

- Gitlink `shared` удалён из индекса, `.gitmodules` удалён, локальная настройка
  submodule.shared снята. `shared/` больше не участвует в рабочем дереве.
- Необходимые библиотеки, тесты и ReleaseKit из коммита
  `d3d9498820704a2faf6c602e87fe91b501b0d391` стали обычными файлами `core/`.
  Включены также родительские настройки тестов и PlatformFacts. Исходные хеши
  и происхождение сохранены в `core/import-manifest.json` и `core/ORIGIN.md`.
- Код стенда SipCheck находится непосредственно в `tools/SipCheck/`; его
  Windows-проект и реализация WASAPI не импортированы. WPF-приложение,
  WASAPI-проекты и Windows-обновляльщик в решение не входят.
- Настройки компилятора и версия Linux находятся в корневом
  `Directory.Build.props`. Локальные библиотеки наследуют их через
  `core/Directory.Build.props`; унаследованная версия Windows больше не нужна.
- Все ProjectReference ведут внутрь Linux-репозитория. Решение содержит
  37 проектов, включая 15 тестовых; добавлены существующие проверки
  EliteSIP.Updates.Tests, ранее не включённые в Linux-решение.
- Значки, рингтон, emoji.pak и входные данные генератора палитр локальны.
  Лицензионные условия проекта и сторонних пакетов сохранены.
- Приложение пишет ревизию Linux в поле SourceRevision и справку поддержки.
  Архив исходников без Git собирается с явной отметкой source-archive.
- CI использует обычный checkout одного репозитория: без submodules,
  SHARED_REPO_TOKEN и загрузки Windows-меток.
- Скрипты сборки пакета, выпуска и публикации используют локальные ресурсы
  и ReleaseKit. Выпуск проверяет чистоту Linux-дерева и собственную версию;
  проверка опубликованной метки Windows удалена. Проверки ключей, подписи,
  канала и порядка публикации сохранены.

Изменения поведения из Windows Mychanges.md на этом этапе не переносились.
Из пользовательских диагностических строк изменено описание происхождения
сборки; версия Linux осталась 0.1.7. Windows-репозиторий не изменён.

## Проверки

- Release-сборка решения: успешно, 0 предупреждений и 0 ошибок.
- Все тесты в отдельной копии исходников без старых bin/obj и подмодуля:
  **1269 прошли, 0 ошибок, 2 пропущены как Windows-only**, всего 1271 тест
  в 15 проектах. Проверена также отметка source-archive.
- Из отдельного обычного локального клона собран `.deb` версии **0.0.0**
  с конфигурацией-заглушкой `https://update.invalid`. Клон не содержит
  .gitmodules, gitlink или доступа к Windows-репозиторию.
- В пакете проверены приложение, обновляльщик, заглушка конфигурации,
  systemd-службы/таймер/путь, автозапуск, значки пяти размеров, документация,
  исполняемые права программ и принадлежность всех записей root/root.
- Ссылки проектов не выходят за репозиторий; bash-синтаксис скриптов и
  `git diff --check` проверены. В рабочих файлах сборки/CI отсутствуют
  обращения к Windows-репозиторию и его меткам.

Итоги по наборам тестов: [verification.json](2026-11-14-independent-verification.json).
Пакет тестовый: не подписывался как выпуск, не устанавливался и не публиковался.
GitHub Actions в удалённом репозитории не запускался. Реальные звонки,
проверки оборудования и обновление установленного клиента этим этапом не выполнялись.
