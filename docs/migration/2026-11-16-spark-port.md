## События машины

Журнал передаёт необязательные `peer_number` и `peer_name`, события `crash`
и `connection`, причины переподключения, запуск и штатный выход. Номер и имя
берутся из реальной записи звонка; старый буфер без этих полей не обогащается
задним числом. Значения ограничены по длине, секреты маскируются.
Файл очереди и временный файл на Linux имеют права 0600.

Отдельный маркер запуска позволяет при следующем старте сообщить о нештатном
прошлом выходе, не приписывая ему вымышленную причину. Пережитая ошибка не
превращает штатное завершение в аварию. Сброс машины забывает буфер и удаляет
маркер и временный файл. На выходе выполняется асинхронная попытка отправки
с ожиданием не более 750 мс; при недоступной сети события остаются на диске.

## Дом / офис и связь

Последний выбор оператора хранится в `Panel.PendingWorkFormat` и переживает
перезапуск. Отправки идут последовательно; выбор, изменившийся во время
запроса, отправляется следом. Неудачная отправка не создаёт бесконечный цикл:
повтор происходит при следующей синхронизации. Ответ прежней привязки не
очищает очередь новой. Конфигурация сервера не затирает ещё не отправленный
выбор, кроме действительного закрепления известной площадки.

`work_format_locked` читается из подписанной конфигурации и участвует в её
отпечатке, поэтому изменение закрепления замечается даже при прежней ревизии.
Переключатель Avalonia использует проверяющий setter модели. Закреплённый офис
также блокирует «Исправить сеть»; разрешённое административным доступом
переключение поверх закрепления сначала переводит машину в ручной режим.
Возврат под управление Spark отменяет локальную очередь и восстанавливает
серверную площадку. Обновление площадки самой конфигурацией не создаёт
обратный запрос как будто это выбор оператора.

Серия ожидающих переподключений объединяется до последнего запроса.
После неожиданного закрытия SIP-канала выполняется отложенное восстановление
только для ещё актуального агента. Во время разговора переподключение остаётся
отложенным до его окончания.

Статус больше не выводится только из режима Managed: до ответа связь не
проверена, после ошибки показана недоступность. Успешный статус означает
доступность канала настроек, а не доказательство работоспособности всех
сервисов Spark. Отметка текущего запуска не сохраняется между запусками;
старое время контакта само по себе не даёт статус доступности.

## Восстановление привязки

Проверка окна восстановления выполняется по сохранённым данным машины также
в ручном режиме и не зависит от пропущенных версий приложения. Снимок
подписывается HMAC от SIP-пароля каждой линии; сами пароли и ключ канала
в снимок не попадают. Только HTTP 202 запоминается как принятая заявка;
сохранённая отметка предотвращает повторную отправку после перезапуска.
Ответ старой привязки не подтверждает новую. Закрытие клиента отменяет запрос.

Локальный серверный контракт допускает в предустановках только UDP/TLS.
Для TCP восстановление заявки пропускается с диагностикой: клиент не выдаёт
реальную TCP-конфигурацию за UDP. Расширение этого контракта требует отдельной
серверной работы.

## Серверный контракт и проверки

Сверены исходники Spark коммита
`6cf58351d3daa106e524a6b47349cf4e70a6c253`:

- `backend/internal/httpapi/elitesip_work_format.go`: POST
  `/api/pair/work-format`, BasicAuth машины, JSON `work_format`, успех 204,
  закрепление 409. Ошибки авторизации и отсутствующий обработчик сохраняют
  очередь клиента для последующего повтора.
- `backend/internal/httpapi/elitesip_recovery.go` и
  `backend/internal/elitesip/recovery.go`: GET окна 204/404, POST с `payload`
  и `proofs`, принятие 202. Повторное открытие истёкшего окна — серверная
  административная операция, Linux-клиент её не вызывает.
- `backend/internal/elitesip/events.go`: поля собеседника и виды событий
  `crash` / `connection` присутствуют в контракте.

Автоматическая проверка: 15 наборов, **1367 успешно, 0 ошибок, 2 прежних
Windows-теста пропущено**. После общего прогона затронутые наборы повторены:
